## 3.5 stable release

- Zoom and picture size in sessions, an on-screen notice while someone is connected, and live online status for saved desktops.

## 3.4 stable release

- Closing the app ends sessions and processes, unattended access is a separate option, and saved desktops can be managed.

## 3.3 stable release

- Direct peer connections with a relay fallback, H.264 video, Opus voice, more ID directories and a new look.
- Results and untested cases are in [VALIDATION_3_3.md](VALIDATION_3_3.md).

## 3.2 stable release

- A desktop whose clock is wrong can now be found by ID. Details are in the changelog.

## 3.1 stable release

- More reliable connection by ID, video paced to the connection, lighter voice and clearer offline messages.
- Results and untested cases are in [VALIDATION_3_1.md](VALIDATION_3_1.md).

## 3.0 stable release

- In-app update window, free local mouse, local network setting, faster file transfer with progress, clearer folder sharing and voice status.
- Results and untested cases are in [VALIDATION_3_0.md](VALIDATION_3_0.md).

## 2.9 stable release

- A saved device answering with an older protocol is refused, and passwords are not sent to a desktop that cannot prove its identity.
- DNS over HTTPS recovery, light theme, session audio controls and the first OpenDesk Lite downloads.
- Results and untested cases are in [LITE_AND_COMPATIBILITY_VALIDATION.md](LITE_AND_COMPATIBILITY_VALIDATION.md).

## 2.8 stable release

- One public version number across the app, Windows metadata, installer, release downloads and update manifest. The Rust package uses the equivalent 2.8.0 representation.
- Stable and explicitly Latest in both the original repository and portfolio fork.
- Foreground incoming approval, repeated-request handling, remote controller cursor visualization, capture-independent input, prioritized voice/control delivery, decoder recovery and audio-device diagnostics from the latest native implementation.
- Historical release numbers, original tags and source commits are recorded in [RELEASE_MAPPING.json](RELEASE_MAPPING.json). Original downloadable binaries remain in the canonical repository; mirrored historical release pages provide direct links to the same files.
- Native 3.0.0-alpha installations require the 2.8 installer once because their older updater considers 2.8 numerically lower. Existing settings/device identity are preserved. Thereafter releases advance 2.9, 3.0, 3.1, etc.
- Archived manifests and executable names are retained as historical artifacts. Use the current root version.json and current stable installer for updates.
